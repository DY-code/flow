# Flow

> 接管你的大脑工作记忆负载。让想法不丢、上下文不断、任务可回滚。

Flow 是一个面向复杂思考、长期项目与研究整理场景的本地优先工具。它把零散想法组织成树状逻辑链，并配合 Markdown 编辑、版本回滚、导出备份与 PWA 离线能力，帮助你把“脑内暂存上下文”沉淀成可追溯、可恢复、可继续推进的工作流。

## 适合谁

- 需要长期维护复杂上下文的研究者、学生、写作者
- 经常被打断，需要快速恢复工作现场的开发者、产品、内容创作者
- 希望把临时思路、问题分析、行动计划沉淀成结构化记录的任何人

## 核心能力

- 树状大纲编辑：把问题、假设、证据、结论、行动拆成节点结构
- 思维流视图：用独立浮层展示项目推进过程，区分主线、支线与计划节点
- 双栏协同工作流：左侧看逻辑链，右侧写正文内容
- 经典 / 简约大纲：经典模式完整编辑结构，简约模式更适合快速浏览和轻量编辑
- 聚焦模式：只查看某个节点及其子树，减少噪音
- Markdown 深度记录：支持正文编辑、预览、节点导入导出
- 状态管理：节点支持 `waiting`、`inProgress`、`completed`、`onHold`
- 版本回滚：保存关键版本，也可查看当前项目的 GitHub 历史版本并回溯
- 导出与备份：支持导出 `JSON`、`Markdown`，也可推送到 GitHub
- 最近项目管理：区分 `global`、最近导入 JSON 与 GitHub 项目列表
- global 工作流：支持任务计划、今日待办、节点导入与完成情况回写
- PWA 离线体验：可安装为桌面应用，在离线环境继续使用

## 界面与工作流概览

Flow 的使用方式可以理解为“左边搭结构，右边写内容”。

- 左侧 `逻辑链 & 思维流`：管理节点层级、顺序、状态和聚焦范围，并可打开思维流浮窗
- 右侧 `Editor`：编辑当前节点的标题、摘要、正文，并可切换预览
- 顶部工具区：切换视图、布局、显示细节、背景主题、导出与备份
- `Focus Mode`：将某个节点作为当前上下文，仅查看该节点与其子树
- `经典 / 简约`：在左侧大纲顶部切换大纲样式
- `思维流视图`：独立于大纲，用可拖动、可缩放、可调整大小的浮层展示当前完整项目

比较适合的典型流程是：

1. 新建一个项目，先搭出一级或二级节点骨架
2. 逐个节点写标题、简述和正文内容
3. 用状态标记当前进度，把不重要的节点先搁置
4. 需要深挖时进入聚焦模式，专注处理一个局部问题
5. 用思维流视图检查项目主线、支线和计划节点是否清晰
6. 在关键阶段保存版本，并导出或推送到 GitHub 做备份
7. 需要恢复时，从本地版本或 GitHub 历史版本中回溯

## 快速开始

### 前置要求

- Node.js 18 及以上
- npm

### 安装依赖

```bash
npm install
```

### 启动本地开发环境

```bash
npm run dev
```

默认会启动前端开发服务。启动后按终端输出地址在浏览器中打开即可。

## 运行方式与 npm 脚本

项目当前包含以下常用脚本：

| 脚本 | 用途 |
| --- | --- |
| `npm run dev` | 启动前端开发环境 |
| `npm run dev:git` | 只启动本地 Git 备份服务 |
| `npm run dev:all` | 同时启动前端和 Git 备份服务 |
| `npm run build` | 构建生产版本 |
| `npm run preview` | 本地预览构建产物 |
| `npm run pwa:serve` | 以 `4173` 端口预览 PWA 构建结果 |
| `npm run pwa:start` | 先构建，再启动 PWA 预览服务 |

建议这样理解：

- 只想本地体验核心界面和编辑功能：使用 `npm run dev`
- 需要测试“导出并推送到 GitHub”：使用 `npm run dev:all`
- 需要安装 PWA 或验证离线体验：使用 `npm run pwa:start`

## 基础使用流程

### 1. 创建项目

启动应用后，你可以从空白项目开始，也可以导入已有的项目数据。

- 空白项目会自动创建一个初始根节点
- 项目名称支持在界面顶部直接修改
- 所有内容默认优先保存在浏览器本地存储中
- `Import JSON` 可导入已有项目文件
- 最近通过 `Import JSON` 打开的本地项目会出现在“最近项目”菜单中

### 2. 在大纲中组织逻辑链

左侧大纲区用于搭建结构。

- 使用新增节点操作，把大问题拆成多个子问题或步骤
- 通过缩进和反缩进表达父子层级
- 为节点设置状态，区分待做、进行中、已完成、暂缓
- 通过折叠、聚焦与隐藏 `onHold` 节点降低干扰

如果你是用来整理研究、任务或写作，比较自然的方式是：

- 一级节点放主题、阶段或章节
- 二级节点放问题、假设、任务、材料或证据
- 正文里再记录详细分析过程

大纲区支持两种样式：

- `经典`：保留完整结构编辑能力，包括新增、删除、拖拽、缩进、反缩进、状态修改等
- `简约`：更适合浏览和轻量维护，支持选择节点、折叠 / 展开、聚焦，以及编辑节点名称和状态

简约样式不会修改真实层级和结构逻辑。它只改变视觉呈现：当连续父子节点满足压缩条件时，会减少视觉缩进，并用垂直箭头表达递进关系；存在并列子节点时保持普通树状缩进。

### 3. 编辑节点内容

右侧编辑区对应当前选中的节点，通常包含三层信息：

- 标题：节点名称
- 摘要：用于快速说明节点意图
- 正文：Markdown 正文，适合写分析、记录、结论、计划

你可以在编辑区中：

- 直接编辑 Markdown 内容
- 在编辑和预览之间切换
- 导出当前节点的 Markdown
- 导入外部 `Markdown` / `txt` 内容追加到节点正文

### 4. 使用视图与聚焦功能

Flow 支持多种查看方式，适合不同设备和工作阶段。

- `split`：同时查看大纲和编辑器，是默认工作模式
- `editor`：只看编辑区，适合专注写作
- `outline`：只看大纲，适合整理结构
- 横向 / 纵向布局切换：适配不同屏幕和个人习惯
- `Focus Mode`：只处理某个节点和它的子树

### 5. 使用思维流视图

左侧大纲顶部的思维流按钮会打开一个应用内浮层窗口。这个窗口与现有大纲独立，只负责展示，不直接编辑结构。

思维流视图的特点：

- 浮层窗口可拖动、可关闭、可调整大小
- 画布支持拖动和平移，也支持缩放
- 只显示节点标题，悬停节点时展示标题、摘要、状态、最近修改时间
- 点击节点可选中对应大纲节点，窗口保持打开
- 主线使用主题色标注连接线和边框，支线保持较浅样式
- 主线横向推进，支线上下展开，整体更接近“思考推进过程”而不是传统大纲

主线规则：

- `[计划] ` 开头的根节点视为计划节点，作为最上方支线区展示，不参与主线判定
- 第一个非计划根节点作为主线入口
- 每个同级节点中的第一个节点继续作为主线节点
- 其他同级节点作为支线
- 打开窗口时默认展开项目根、所有主线节点，以及每个主线节点的直接子节点
- 直接支线节点默认不继续展开，单击支线节点可展开 / 收起下一层

### 6. 使用最近项目与 global 工作流

顶部“最近项目”菜单分为三类：

- `Global`：固定展示 `flow-projects/global/` 下的全局项目
- `最近本地项目`：展示最近通过 `Import JSON` 打开的本地项目
- `GitHub 项目列表`：折叠展示已进入本地 Git 备份目录的普通项目记录

`global` 工作流适合把跨项目复用的计划、待办和节点片段集中管理：

- 当 `global` 目录为空时，可以快速创建默认“任务计划”
- 普通项目中可以把当前节点导入到 `global`
- 普通项目中也可以从 `global` 导入节点到当前项目
- 任务计划可以生成“今日待办”
- 今日待办完成情况可以回写到任务计划

### 7. 保存版本与回滚

当你完成一个阶段性整理后，建议保存版本。

- 应用支持保存版本历史
- 可以在关键节点形成一个可回退的检查点
- `Ctrl/Command + Shift + S` 会保存当前版本，并导出一个版本备份文件
- `Version History` 中可以查看本地版本，也可以查看当前项目的 GitHub 历史版本
- GitHub 历史回溯只覆盖当前应用状态和浏览器缓存，不修改磁盘上的 JSON 文件

这对研究整理、方案推演、长文写作尤其有用，因为你可以放心尝试重组结构，而不必担心彻底丢失上一个稳定状态。

### 8. 导出与备份

项目支持多种导出方式：

- 导出完整项目为 `JSON`，适合继续导入 Flow
- 导出为 `Markdown`，适合归档或交给其他工具处理
- 推送到 GitHub 仓库，适合长期备份和跨设备保存

### 9. 理解项目保存状态

项目标题附近的圆点用于提示最近一次保存相关状态：

- 橙色闪烁：当前应用中有未保存 / 未导出的修改，优先级最高
- 绿色：最近一次操作是导出或本地保存
- 黄色：最近一次操作是保存版本
- 雾蓝色：最近一次 GitHub 推送成功

## GitHub 备份推送

如果你要使用“导出并推送到 GitHub”，推荐按下面的方式操作。

### 前置条件

- 本机已安装 `git`
- 当前环境已配置可用的 GitHub 凭据
- 你准备好了目标仓库地址

### 启动方式

```bash
npm run dev:all
```

这个命令会同时启动：

- 前端应用
- 本地 Git 备份服务，默认端口为 `5174`

### 使用方式

1. 在应用中打开 `Export`
2. 选择“推送到 GitHub”
3. 填写仓库地址
4. 根据需要配置代理
5. 可先执行连接测试
6. 执行推送

### 备份文件位置

推送相关的项目文件会保存在项目根目录下的 [flow-projects](/home/dycc/文档/A-app开发/flow/flow-projects) 中。

默认约定：

- 备份分支为 `main`
- 项目文件以 `JSON` 形式保存
- 全局项目会保存在 `flow-projects/global/` 下
- 推送到 GitHub 时，远端仓库中会使用 `projects/` 目录保存项目文件
- 每次推送会镜像整个本地 `flow-projects` 目录，而不是只提交当前项目文件

### 代理与连接测试

GitHub 推送弹窗支持配置 HTTP / HTTPS 代理。代理设置只影响本应用通过本地 Git 服务发起的 Git 操作，不会修改系统全局代理。

`Version History` 中的 GitHub 历史读取会复用同一组仓库地址与代理设置。

### GitHub 历史回溯

`Version History` 支持查看当前项目文件在 GitHub 仓库中的历史版本。

工作方式：

- 历史来源是 GitHub 仓库 `main` 分支中的提交历史
- 查询对象是当前项目对应的 `projects/<项目路径>`
- 列表展示的是当前项目文件在不同提交中的历史版本
- 点击“查看”后会读取该提交中的项目 JSON，并展示项目名、节点数、最近修改时间和提交哈希
- 点击“回溯到此版本”会覆盖当前应用状态和浏览器本地缓存
- 回溯不会修改磁盘上的 JSON 文件，也不会自动再次推送 GitHub

注意：当前 GitHub 推送会镜像整个 `flow-projects` 目录，因此某条提交信息可能包含其他项目名。历史列表会优先显示当前查询的项目路径、提交时间和短哈希，提交信息只作为辅助信息。

## PWA 安装与离线使用

如果你希望把 Flow 当作桌面应用长期使用，建议安装 PWA 版本。

### 正确启动方式

不要在 `npm run dev` 模式下直接安装 PWA，建议使用：

```bash
npm run pwa:start
```

然后打开：

```text
http://localhost:4173
```

再从浏览器菜单或地址栏中执行安装。

### 为什么这样做

`npm run dev` 主要用于开发调试，而 PWA 的安装、缓存和离线能力更适合在构建产物预览环境中验证。使用 `pwa:start` 可以更接近真实安装体验。

## 数据存储与项目文件说明

Flow 是本地优先工具，数据主要围绕以下几类存储与导出方式展开：

- 浏览器 `localStorage`：用于日常编辑过程中的即时持久化
- 浏览器 `IndexedDB`：用于记录最近导入的本地 JSON 项目文件句柄
- `JSON` 项目文件：用于完整导出、导入与 Git 备份
- `Markdown` 文件：用于通用文本归档和内容迁移
- 版本历史：用于保存关键阶段快照并在需要时回滚
- `flow-projects/`：本地 Git 备份服务使用的项目镜像目录
- GitHub 仓库 `projects/`：远端备份中的项目文件目录

一个项目数据通常包含：

- 节点树结构
- 每个节点的正文内容
- 当前激活节点与聚焦节点
- 布局模式和部分界面设置
- 项目元数据，例如创建时间、最后修改时间、最后导出时间

最近本地项目只记录最近通过 `Import JSON` 打开的文件入口。浏览器权限失效时，需要重新选择文件。

## 注意事项

- PWA 安装请使用 `npm run pwa:start`，不要直接在 `npm run dev` 环境安装
- 如果要使用 GitHub 推送，必须先确认本机 `git` 与认证凭据可用
- GitHub 历史回溯只覆盖当前应用状态和浏览器缓存，不会修改磁盘 JSON 文件
- GitHub 推送成功后的雾蓝色圆点只表示最近一次 GitHub 推送成功；一旦有本地未保存修改，会优先显示未保存状态
- 简约大纲只提供轻量编辑能力，不支持新增、删除、拖拽或修改节点结构
- 思维流视图暂时只用于展示，不提供直接编辑能力
- `Delete` / `Backspace` 会直接执行删除确认；删除子树不可撤销
- 版本保存适合作为阶段性检查点，但仍建议定期导出 `JSON` 或推送到 GitHub 做额外备份

## 总结

Flow 不只是一个记笔记工具，更适合承担“结构化思考工作台”的角色。它适合那些需要长期维护上下文、反复回到复杂问题现场、并希望把思考过程沉淀为可恢复工作流的人。

如果你希望进一步完善它，最推荐的使用顺序是：

1. 先用 `npm run dev` 熟悉基础编辑与结构整理
2. 用经典 / 简约大纲和思维流视图检查结构是否清晰
3. 再用 `Ctrl/Command + Shift + S` 建立版本保存习惯
4. 最后结合 `npm run dev:all`、GitHub 备份和 GitHub 历史回溯完成长期保存
